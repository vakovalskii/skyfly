# ПОЛЁТ — устройство проекта

Карта текущего рабочего дерева после перехода на `character/gravity/grid`.
Общие команды запуска и проверки — в [README](../README.md).

## Слои

```text
game/input → keys → core/character → состояние персонажа
                        ↕
                   game/world → core/collide
                        ↕
                 render/terrain + render/city

src/main → камера, герой, эффекты, звук, HUD, сеть → кадр
```

| Модуль | Ответственность |
|---|---|
| `src/main.js` | Сборка компонентов, загрузка героя, старт городов, цикл кадра, обработчики игровых событий |
| `core/grid.js` | Локальные и географические координаты, расстояние/азимут, Mercator, кривизна, плотность воздуха |
| `core/gravity.js` | Гравитация по высоте, сопротивление падению, оценка силы удара, рост и высота ступеньки |
| `core/character.js` | Состояние героя, режимы `ground/air/fly`, движение, зарядка, энергия, контакт с миром |
| `core/collide.js` | Сетка высот крыш с клеткой 10 м; включает клетку, если её центр внутри контура здания |
| `game/world.js` | Города и рельеф, `floorAt`, `move`, `sync`, `spawnOnRoof` |
| `game/input.js` | Мышь/клавиатура и touch → взгляд, флаги ввода |
| `game/camera.js` | Камера от третьего лица, сглаживание, тряска, ограничение по высоте опоры |
| `game/hud.js` | Скорость, высота, сила, компас, чат, сообщения и помощь |
| `game/audio.js` | Ветер и форсаж, CC0-сэмплы шагов/ткани/взлёта, свист около зданий, приземление и сверхзвук |
| `game/net.js` | WebSocket, отправка состояния, reconnect, чат |
| `game/players.js` | Модели удалённых игроков, сглаживание снимков и подписи |
| `game/poseeditor.js` | Редактор поз по клавише P, выбор клипов и поворотов костей |
| `render/terrain.js` | Загрузка снимков/высот и меши рельефа |
| `render/city.js` | Здания OSM, тайлы 400 м, геометрия и детализация по расстоянию |
| `render/hero3d.js` | GLB-модель, скелет, смешивание анимаций и поза полёта |
| `render/hero.js` | Процедурный герой до загрузки GLB |
| `render/sky.js` | Небо, звёзды, глобус, атмосфера |
| `render/tex.js` | Процедурные текстуры на canvas |
| `render/style.js` | Режим grid/full из URL или localStorage, по умолчанию grid |
| `render/flypose.js` | Настройки клипов и костей, сохранение в localStorage `skyfly-anim` |
| `render/wind.js`, `fx.js`, `post.js` | Ветер, конус Маха, следы, ударные волны, постобработка |
| `server.js` | Пересылка позиций и чата, без серверной физики |

Пути `core/`, `game/`, `render/` в таблице указаны относительно `src/`.
`flight.js` и `geo.js` удалены в текущей переделке. `main.js` содержит также
пороги эффектов и преобразования координат; это не только декларативная сборка.

## Координаты и высота

- Состояние: `c.lat`, `c.lon` — градусы; `c.alt` — метры над уровнем моря.
  Проверка контакта в `stepCharacter` трактует `alt` как **высоту ног**.
- Скорость `c.vel`: `[восток, вверх, север]`, м/с.
- Локальная пара аргументов `floorAt(east, north)` — метры от игрока.
- Сцена Three.js: восток `+X`, вверх `+Y`, север `−Z`.
  Рельеф получает вертикальное смещение `−c.alt`; мир движется вокруг игрока.
- Здания в JSON: контуры `p = [east, north, ...]` относительно центра города,
  `h` — высота здания. Города дополнительно опускаются по кривизне Земли.

Сейчас это **не единая реализация преобразований**: `grid.js` содержит и
плоское приближение, и сферические расстояния; `terrain.js` повторяет формулы;
генератор OSM использует ещё одну локальную проекцию. `hero.position.y = -HEIGHT`
не согласован с высотой ног. Эти расхождения требуют исправления, проверяйте опору и высоту персонажа при изменении физики.

## Физика и связь с миром

`newCharacter(lat, lon)` создаёт героя. `stepCharacter(c, keys, dt, events)`
меняет состояние на месте и возвращает скорость, плотность воздуха и данные
для эффектов. Интерфейс мира:

- `floorAt(east, north)` → абсолютная высота опоры: рельеф + крыша;
- `move(lat, lon, east, north)` → новая пара `[lat, lon]`;
- события `onJump`, `onTakeoff`, `onFly`, `onTired`, `onWall`, `onLand`.

`main.js` передаёт эти функции через объект `events`, также доступный как
`world.events` для браузерного теста. Отдельного `headroomAt` в коде нет.

Режимы:

| Режим | Действие |
|---|---|
| `ground` | W/S, A/D — разворот, Q/E — шаг вбок; шаг 1,8 м/с, Shift — бег 6 м/с и разгон 14 м/с² до сверхбега 45 м/с; пробел — заряженный прыжок 7–500 м |
| `air` | Свободное падение, слабое горизонтальное управление; новое нажатие пробела включает `fly`, если силы > 5 |
| `fly` | Полёт по взгляду; в зависании Space без W — вертикальный подъём (24 м/с, с Shift 65 м/с), отпускание — остановка подъёма; Ctrl/C — вниз, X — тормоз, F — выключить полёт |

Удержание пробела на опоре дольше 0,45 с с последующим отпусканием запускает
заряженный взлёт. Сила расходуется в `fly`, восстанавливается в `ground/air`.
`keys.jump` от Space используется и для подъёма в полёте. `hoverLift` сохраняет
вертикальную позу при подъёме/снижении; горизонтальное управление возвращает обычный полёт.

Порядок кадра сейчас: `world.sync(c)` → возможный spawn → `stepCharacter` →
камера/герой/эффекты → HUD → отправка состояния → рендер. Поэтому трансформы
мира и `city._off` вычислены до движения текущего кадра. При изменении порядка
нужно отдельно обеспечить актуальную опору для физики и трансформы для рендера.

## Мир и ресурсы

`public/data/moscow.json` и `spb.json` загружаются после нажатия старта.
Москва ожидается через `await`, Петербург запускается следом в фоне.
`tools/fetch-osm.mjs` получает здания и воду через Overpass; кэш запросов — `.cache/`.

Рельеф: снимки ESRI World Imagery и высоты AWS Terrain Tiles, Terrarium PNG.
Кольца зумов: 16/14/12/10/8, каждое 5×5; выше 14 высоты берутся из родительского
тайла. Ограничение параллельных загрузок — 1 на мобильном устройстве, 2 на ПК.
`terrain.ground(lat, lon)` сейчас использует выбранный тайл под игроком,
а не ищет произвольный тайл по координатам запроса.

Здания группируются в тайлы 400 м. Геометрия создаётся порциями (1/3 на кадр
для телефона/ПК); полный вид до 3500 м, упрощённый — до 14000 м.
Коллизии приближённые: проверяется центр клетки 10 м, поэтому мелкие здания
могут не попасть в сетку, а граница фасада определяется с точностью клетки.
Надстройки на крышах в этой сетке не учитываются.

В появившемся во время разбора режиме `grid` снимки не скачиваются, высоты
продолжают загружаться. `?style=full` возвращает текстуры; редактор поз открывается
клавишей P. В открытом редакторе ввод очищается, шаг физики получает `dt = 0`.

Основная модель — `public/models/hero-base.glb`, полёт использует
`Swim_Fwd_Loop` по умолчанию из `flypose.js`, поверх накладывается поза костей.
Учёт лицензий — `public/models/LICENSES.md`; его таблица
и раздел «НЕ включено» противоречат друг другу в отношении `hero-base.glb`.

## Сеть и запуск

`npm run dev` запускает Vite и WS-сервер. Vite: `127.0.0.1:5174`.
WS: `8791` по умолчанию (переменная `PORT` меняет сервер, но не локальный URL клиента).
Клиент на localhost подключается прямо к `8791`, на другом hostname — к `/fly-ws`.
Для доступа по LAN одной смены Vite host недостаточно: нужен маршрут WS.

Сообщения: `hi`, `join`, `s` (состояние), `snap` (снимок игроков), `chat`.
Сервер рассылает снимки раз в 84 мс; клиент ограничивает отправку интервалом
80 мс. Позиции рассчитывает клиент; сервер ограничивает размер сообщения и
диапазоны чисел, но не проверяет движение физикой.

`npm run build` создаёт `dist/`. `BASE=/fly/ npm run build` задаёт production base.
Общий порядок размещения описан в [DEPLOYMENT.md](DEPLOYMENT.md).

## Проверки

Команды — в [README](../README.md). Браузерный self-test проверяет загрузку
рельефа, координаты, крышу, видимость героя, ходьбу/бег/остановку, прыжок,
падение/удар, включение полёта, форсаж и наличие аудиоконтекста.
Он зависит от живого кадра, сети и геометрии места старта, поэтому не заменяет
детерминированные тесты расчётов.
